# ابزار مشترک توسعه (dev-tools)

یک ابزار برای همه‌ی پروژه‌ها. پروژه‌های جنگو (Django) و دات‌نت (.NET) را پشتیبانی می‌کند.

## این ابزار چطور کار می‌کند؟

1. در هر پروژه فقط فایل کوچک `dev.cmd` هست. این فایل در همه‌ی پروژه‌ها **دقیقاً یکی** است.
2. خود ابزار (`dev.ps1`) فقط در این مخزن است.
3. `dev.cmd` بار اول ابزار را در این پوشه دانلود می‌کند:
   ```
   %LOCALAPPDATA%\dev-tools
   ```
   بعد از آن، در هر اجرا نسخه‌ی جدیدش را می‌گیرد (چند کیلوبایت).
4. تنظیمات مخصوص هر پروژه در فایل `dev.json` همان پروژه است.

پس اصلاح ابزار فقط یک جا انجام می‌شود و همه‌ی پروژه‌ها فوراً نسخه‌ی جدید را دارند.

## افزودن به یک پروژه‌ی جدید

1. فایل `dev.cmd` همین مخزن را در پوشه‌ی اصلی پروژه کپی کنید.
2. اگر تنظیم خاصی لازم است، فایل `dev.json` بسازید (نمونه: `dev.example.json`).
3. روی `dev.cmd` دو بار کلیک کنید.

نوع پروژه خودکار پیدا می‌شود:
- اگر `manage.py` باشد: جنگو
- اگر فایل `.slnx` یا `.sln` باشد: دات‌نت
- در غیر این صورت: فقط گزینه‌های گیت

## منو

| شماره | گزینه | توضیح |
|---|---|---|
| 1 | Start work | گرفتن آخرین کد، نصب بسته‌ها، به‌روزرسانی دیتابیس، اجرای سایت |
| 2 | Run site only | فقط اجرای سایت |
| 3 | Make migrations / Build | جنگو: ساختن مایگریشن. دات‌نت: ساختن برنامه |
| 4 | Finish work | ذخیره و فرستادن به گیت‌هاب |
| 5 | Get latest | فقط گرفتن کد جدید از گیت‌هاب |
| 6 | Status | وضعیت: نسخه، شاخه، تغییرهای فرستاده‌نشده، پورت همه‌ی پروژه‌ها |
| 7 | Open site | باز کردن سایت در مرورگر |
| 8 | Default data / History | جنگو: داده‌ی پیش‌فرض. دات‌نت: تاریخچه‌ی آپدیت |
| 9 | Publish | انتشار برای سرورها (اگر تنظیم شده باشد) |
| 10 | Source zip | کد به صورت زیپ روی دسکتاپ (برای چت جدید) |
| 11 به بعد | Tools | ابزارهای اضافه‌ی همان پروژه از `dev.json` |

هر گزینه فقط وقتی دیده می‌شود که برای آن پروژه معنی داشته باشد.

**توقف سایت:** در پنجره‌ی سایت Enter یا Ctrl+C بزنید. فقط سایت بسته می‌شود و به منو برمی‌گردید.

## اجرا با دستور (بدون منو)

```
dev.cmd start      همان گزینه‌ی 1
dev.cmd run        فقط اجرای سایت
dev.cmd pull       گرفتن کد جدید
dev.cmd push       ذخیره و فرستادن
dev.cmd status     وضعیت
dev.cmd build      ساختن (دات‌نت)
dev.cmd publish    انتشار
dev.cmd zip        زیپ سورس
```
ابزارهای `dev.json` هم با نام `command` خودشان اجرا می‌شوند.

## پورت‌ها (اجرای هم‌زمان چند پروژه)

- هر پروژه پورت خودش را در `dev.json` دارد.
- فهرست پورت همه‌ی پروژه‌های این کامپیوتر در این فایل است:
  ```
  %LOCALAPPDATA%\dev-tools-data\ports.json
  ```
- اگر پورت یک پروژه با پروژه‌ی دیگری یکی باشد، ابزار خودش یک پورت آزاد انتخاب می‌کند و در `dev.json` می‌نویسد.
- اگر `port` در `dev.json` نباشد، ابزار خودش یکی انتخاب می‌کند.

نکته برای جنگو: مرورگر کوکی‌ها را بر اساس آدرس نگه می‌دارد، نه پورت. پس هر سایت جنگو باید نام کوکی جدا داشته باشد (`SESSION_COOKIE_NAME` و `CSRF_COOKIE_NAME`). اگر نداشته باشد، ابزار هشدار می‌دهد.

## تنظیمات dev.json

همه‌ی موارد اختیاری هستند.

| نام | توضیح | پیش‌فرض |
|---|---|---|
| `type` | `auto`، `django`، `dotnet` یا `other` | `auto` |
| `port` | پورت سایت | انتخاب خودکار |
| `env` | متغیرهای محیطی اضافه | — |
| `python` | نسخه‌ی پایتون برای ساختن محیط مجازی | `3.13` |
| `setup_commands` | دستورهای `manage.py` بعد از هر به‌روزرسانی (باید تکرارپذیر باشند) | — |
| `seed_commands` | دستورهای داده‌ی پیش‌فرض (یک بار برای هر دیتابیس) | — |
| `dotnet_sdk` | نسخه‌ی لازم دات‌نت، مثلاً `10` | هر نسخه |
| `launch_profile` | پروفایل اجرای دات‌نت | `http` |
| `restart_exit_code` | سایت با این کد بسته شود یعنی «آپدیت کن و دوباره اجرا کن» | `42` |
| `work_branch` | شاخه‌ای که Claude در آن کد می‌نویسد | — |
| `publish_branch` | شاخه‌ای که سرورها از آن نصب می‌کنند | — |
| `release_mode` | `branch`، `tag` یا `none` | خودکار |
| `tools` | گزینه‌های اضافه‌ی منو | — |
| `secret_patterns` | فایل‌هایی که هرگز نباید به گیت‌هاب بروند | `.env`، `*.sqlite3`، `*.pfx`، `*.key`، `*.pem` |

### روش انتشار (release_mode)

- `branch`: گزینه‌ی 9 شاخه‌ی کار را به شاخه‌ی انتشار می‌فرستد. اگر `work_branch` و `publish_branch` باشند، خودکار همین است.
- `tag`: نسخه‌ی فایل `VERSION` به صورت برچسب `v1.2.0` منتشر می‌شود. بعد از «Finish work» هم می‌پرسد.
- `none`: انتشار ندارد.

### ابزارهای اضافه (tools)

```json
"tools": [
  { "title": "Build release", "script": "installer\\release.ps1", "args": "-Action build", "command": "release" }
]
```
- `title`: متن منو
- `script`: مسیر اسکریپت PowerShell در پروژه
- `args`: آرگومان‌ها (اختیاری)
- `command`: نام برای اجرا با دستور (اختیاری)

## امنیت

- قبل از فرستادن، فایل‌هایی مثل `.env` و دیتابیس بررسی می‌شوند. اگر باشند، چیزی فرستاده نمی‌شود.
- پوشه‌ی `.local` مخصوص همین کامپیوتر است و هرگز به گیت‌هاب نمی‌رود. تاریخچه‌ی آپدیت آنجاست.
